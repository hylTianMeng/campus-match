# CampusCrew 功能需求与验收规格

版本：1.0｜基线日期：2026-10-13｜范围：单校 MVP

配套文档：[产品定义](01-product.md) · [业务规则](03-business-rules.md)

## 1. 规格约定

本文件依据完整 DEC-001～066 记录、用户最新补充和原需求初稿。较晚决策替代关系见 [产品文档](01-product.md#11-必须执行的覆盖关系)。P0 必须交付；P1/P2 均在 MVP 外，只是候选，不承诺实现。管理员只有用户、招募、举报、分类标签、私信五类后台，日志作为这些功能的支撑，不另设独立统计模块。

以下功能 ID 是开发与验收追踪编号，不是新的 DEC。每项含优先级、用户故事、入口、输入输出、前后端能力、验收和依赖。页面名称为信息架构建议；接口路径、组件、字段长度和存储结构待技术设计。所有权限必须由后端校验，前端禁用按钮只是辅助。状态、权限与通知的统一规则以 [03](03-business-rules.md) 为准。

## 3. P0 详细功能

### 3.1 M1 账号与认证

#### F-01 注册账号（P0）

- **故事/入口**：作为本校学生，我希望以校园邮箱和密码建立账号；入口“注册”。
- **输入→输出**：校园邮箱、密码、必填昵称 → 唯一账号与认证状态。昵称在注册或首次完善资料阶段收集，交互安排待设计。
- **前端**：展示单校身份说明、邮箱/密码输入、认证引导和重复账号提示。
- **后端**：校验允许域名与邮箱唯一性，安全存储密码摘要；不得用手机号、学号或第三方身份替代确认方式。
- **验收/边界**：同邮箱并发注册最多一个账号；未认证账号不能发布、申请、私信。邮箱标准化、验证码与注册提交先后顺序见 TD-01。
- **依赖/依据**：M2 昵称、F-03；DEC-002、033、062。

#### F-02 登录、退出及会话（P0）

- **故事/入口**：作为用户，我希望用校园邮箱+密码登录并退出；入口“登录/账号菜单”。
- **输入→输出**：邮箱、密码 → 登录会话和账号状态；退出 → 会话失效。
- **前端**：呈现认证引导、封禁只读说明、登录失败提示；全站依据账号状态展示入口。
- **后端**：校验凭据、会话、封禁及注销状态；每次敏感请求重新检查当前权限，不依赖旧页面状态。
- **验收/边界**：封禁者仍可登录只读；注销者不能使用原账号或残留会话；退出后保护接口拒绝访问。会话时效/找回密码待 TD-01。
- **依赖/依据**：F-01、F-35、F-38；DEC-054～055、062、065。

#### F-03 邮箱验证码校园认证（P0）

- **故事/入口**：作为学生，我希望验证邮箱后获得业务权限；入口“校园认证”。
- **输入→输出**：允许的校园邮箱、邮件验证码 → 已认证结果或失败原因。
- **前端**：发送、输入、验证状态和重试提示；未经认证点击交互入口时引导认证。
- **后端**：邮箱验证绑定账号并校验代码有效性；邮件域名、有效期、发送限制待 TD-01；不得只凭填写校园邮箱标记认证。
- **验收/边界**：错误/过期代码不能认证；已认证用户可发布/申请/自由私信；重复验证保持一致，不创建第二账号。
- **依赖/依据**：F-01；DEC-002、020～021、062。

#### F-04 统一授权守卫（P0）

- **故事/入口**：作为用户，我希望访问规则在页面与接口中一致；应用于全站及管理后台。
- **输入→输出**：身份、认证、封禁、系统角色、资源关系、管理限制 → 允许操作或拒绝。
- **前端**：访客可浏览公开招募，只见发布者昵称头像；完整主页和学生交互提供相应权限提示。
- **后端**：普通用户/管理员两种系统角色；发布者与申请者按资源校验；封禁只读；未认证不能用直接请求绕过限制。
- **验收/边界**：修改别人草稿、审批别人招募、读取别人私信均被拒绝；管理员私信访问必须经 F-37 审计门槛。
- **依赖/依据**：各模块；DEC-020、037、055～057；本次角色补充。

### 3.2 M2 个人资料、主页及搜索

#### F-05 个人资料与技能兴趣标签（P0）

- **故事/入口**：作为用户，我希望介绍自己；入口“个人中心—编辑资料”。
- **输入→输出**：昵称必填，头像/学院/年级/简介/技能兴趣标签选填 → 更新资料。
- **前端**：选择已有或创建新技能兴趣标签；空选填字段不阻碍保存。头像上传与招募无图规则分开。
- **后端**：字段校验、标签引用与新增；不新增强制学号、性别、联系方式或信誉分。长度、头像约束待 TD-02。
- **验收/边界**：无头像和学院可正常使用；昵称空值被拒绝；管理员标签合并后已有资料仍能正确检索。
- **依赖/依据**：M1、F-36；DEC-033、063。

#### F-06 主页隐私与搜索设置（P0）

- **故事/入口**：作为用户，我希望分别控制发现及历史展示；入口“个人中心—隐私设置”。
- **输入→输出**：可被搜索、我的发布/申请/队伍四个独立开关 → 保存配置。
- **前端**：默认可搜索、发布公开，申请/队伍不公开；解释关闭搜索不影响发布和申请。
- **后端**：搜索过滤、主页字段投影及业务必要访问权限分别判断；设置对新请求生效。
- **验收/边界**：关闭搜索后用户不出现在搜索结果，但仍能开展业务；关闭“我的发布”不把其公开招募从发现页自动移除；关闭历史展示不删除业务数据。
- **依赖/依据**：F-07～08、M3/M5；DEC-023、034～036。

#### F-07 认证用户个人主页与历史视图（P0）

- **故事/入口**：作为认证学生，我希望了解对方允许公开的资料；入口“用户搜索/招募发布者/申请者”链接、“个人中心”。
- **输入→输出**：目标用户 → 允许查看的资料及历史栏目。
- **前端**：公开申请仅展示招募与岗位，不展示状态、留言、审核结果；公开队伍仅展示通过的招募及岗位，不显示其他成员。本人记录可见其完整状态。
- **后端**：完整主页只对认证用户开放；邮箱、密码、举报身份、管理证据不得随公开资料返回；按关系保留申请双方必要业务视图。
- **验收/边界**：访客直接主页/API 不能拿到完整资料；不公开申请/队伍时他人不能读取；我的队伍从申请历史派生，不建立 Team/TeamMember。撤销/放弃后的队伍历史口径待 TD-06。
- **依赖/依据**：F-04～06、M5；DEC-013、022、034～037。

#### F-08 认证用户搜索（P0）

- **故事/入口**：作为认证学生，我希望主动寻找伙伴；入口“找同学”。
- **输入→输出**：昵称关键词、技能兴趣标签 → 已认证且允许被搜索的用户列表。
- **前端**：搜索结果可进入允许访问的主页、发起私信；空结果提示。
- **后端**：搜索资格及结果过滤，昵称/标签匹配与分页；关闭搜索不等于禁止业务参与者访问资料。
- **验收/边界**：未认证用户、关闭搜索用户不返回；访客不能借此遍历完整主页；搜索字段不得扩展为私信内容、校园邮箱。
- **依赖/依据**：F-03、F-05～07、F-27；DEC-022～023、037。

### 3.3 M3 招募与岗位

#### F-09 手动草稿（P0）

- **故事/入口**：作为发布者，我希望分次填写招募；入口“发布招募/我的草稿”。
- **输入→输出**：可不完整的统一表单 → 私有草稿；编辑/删除 → 新内容/删除结果。
- **前端**：明确保存按钮、继续编辑和删除；不提供自动保存承诺。
- **后端**：仅作者读写，草稿不公开；正式发布才验证全部必填项。
- **验收/边界**：缺岗位或截止仍可存草稿；他人无法读取；不完整草稿不能发布；封禁账号不能保存或删除草稿。
- **依赖/依据**：F-04、F-10～11；DEC-044、055。

#### F-10 统一表单发布（P0）

- **故事/入口**：作为认证学生，我希望公开任务需求；入口“发布招募”。
- **输入→输出**：标题、一级分类、描述、至少一个岗位、截止时间必填；活动时间/地点/标签选填 → 公开招募与发布时间。
- **前端**：各分类同一表单，仅文字和标签，允许新增标签；不提供图片/附件上传。
- **后端**：认证和非封禁校验、完整字段校验；新发布截止必须在未来（实现建议）；发布后立即公开，无待预审流程。
- **验收/边界**：必填缺失拒绝发布；岗位为零拒绝；校园外账号不能取得发布资格；头像上传不受招募文字限制。
- **依赖/依据**：F-03、F-11、F-36；DEC-003～004、029～031、045。

#### F-11 岗位与名额（P0）

- **故事/入口**：作为发布者，我希望按不同岗位招人；入口“草稿/发布表单/招募详情”。
- **输入→输出**：岗位名称、招募人数必填，描述/技能标签选填 → 独立岗位及容量。
- **前端**：发布前可增删岗位，显示逐岗已通过人数和剩余名额。
- **后端**：名额为正整数（实现建议），录取不得超过容量；发布后禁止增删岗位、修改名额；名称/描述/技能的后续可编辑边界待 TD-02，不能绕过结构锁定。
- **验收/边界**：不同岗位容量分别计算；最后名额并发通过最多成功一次；全岗满员立即结束。
- **依赖/依据**：F-10、F-22、F-26；DEC-004、018～019、031、047～048。

#### F-12 发布后一般内容编辑（P0）

- **故事/入口**：作为发布者，我希望更新说明；入口“我的发布—编辑”。
- **输入→输出**：标题、描述、地点、标签等一般内容 → 更新后的招募内容。
- **前端**：岗位增删、名额、截止时间字段锁定；结束后仍不得修改申请结果。已结束或下架时一般内容编辑边界待设计。
- **后端**：字段白名单更新，客户端提交冻结字段也不能改变；编辑不重置发布时间、不解除独立下架、不重开招募（实现建议）。
- **验收/边界**：换标题成功，改名额/截止或增删岗位被拒绝；修改不能造成旧申请丢失。
- **依赖/依据**：F-04、F-10～11、F-34；DEC-018～019。

#### F-13 招募条件删除（P0）

- **故事/入口**：作为发布者，我希望删除没有业务历史的招募；入口“我的发布—删除”。
- **输入→输出**：本人已发布招募 ID → 删除结果或拒绝原因。
- **前端**：有任何申请历史时仅提供结束入口，不提供删除。
- **后端**：检查全量历史申请，不只检查当前待审；删除与首次申请竞争时保证不能两者都成功而留下孤立记录。
- **验收/边界**：无申请可删；已撤回/未通过/过期的历史申请同样阻止删除；草稿删除按 F-09；关联收藏展示策略待 TD-10。
- **依赖/依据**：F-19、F-14；DEC-046。

#### F-14 手动及自动结束（P0）

- **故事/入口**：作为发布者，我希望提前停止招人；入口“我的发布—结束”；自动结束无页面入口。
- **输入→输出**：本人招募或时间/满员事件 → status=ended，end_reason=manual/expired/filled，结束时间。
- **前端**：解释结束后结果锁定、不能重开；展示结束原因及历史入口。
- **后端**：全部岗位满员立即结束；到期即结束且待审 expired；手动结束待审终态见 TD-03，不当作已确认。后台任务延迟时所有写请求仍须检查到期。
- **验收/边界**：最后录取与结束原子提交；结束后拒绝录取、撤销、放弃及再申请；下架/封禁不延长截止；补人新建独立招募。
- **依赖/依据**：F-22～26、F-30；DEC-012、014～016、043、048～051。

### 3.4 M4 发现与收藏

#### F-15 公开列表与组合搜索（P0）

- **故事/入口**：作为访客或学生，我希望找到符合条件的招募；入口“发现组队”。
- **输入→输出**：关键词、分类、标签、可申请状态、截止范围、地点 → 公开招募分页列表。
- **前端**：允许组合、清空筛选和查看空结果；默认隐藏已结束招募。
- **后端**：关键词查标题/描述/标签；结果统一排除下架及封禁隐藏内容。可申请筛选表示招募仍有开放岗位，个人黑名单等资格在详情/提交时另校验。
- **验收/边界**：组合条件同时生效；关键词不能匹配私信或申请留言；截止边界结果不能诱导成功提交到期申请。历史是否提供单独筛选待 TD-02。
- **依赖/依据**：M3、F-34～35；DEC-020、038、040。

#### F-16 稳定排序（P0）

- **故事/入口**：作为浏览者，我希望按新发布或即将截止排序；入口“发现组队—排序”。
- **输入→输出**：latest/deadline 排序选择 → 有序结果。
- **前端**：默认最新发布，提供即将截止；不出现最热或推荐选项。
- **后端**：最新发布按发布时间倒序，同时间以唯一 ID 保证稳定；即将截止按截止时间升序，追加稳定 ID 为建议。
- **验收/边界**：同时间记录顺序稳定；分页排序字段一致；一般内容编辑不被视为新发布。
- **依赖/依据**：F-15；DEC-039、041。

#### F-17 详情与历史访问（P0）

- **故事/入口**：作为用户，我希望了解招募和回看结果；入口“列表/收藏/我的发布/我的申请/我的队伍”。
- **输入→输出**：招募 ID → 可见详情、逐岗容量、当前状态、允许操作。
- **前端**：访客仅见发布者昵称头像；结束详情保留但申请关闭；受治理限制时显示通用不可访问状态。
- **后端**：详情和历史链接均检查管理限制，不能因有旧链接绕过下架；业务双方查看自己的必要历史，不向公众泄露申请列表。
- **验收/边界**：正常已结束详情仍可公开访问；下架内容不通过收藏/历史入口泄露；结束结果不能再改。
- **依赖/依据**：F-07、F-14、F-34～35；DEC-037～038、049～051。

#### F-18 收藏与我的收藏（P0）

- **故事/入口**：作为认证学生，我希望保留感兴趣的招募；入口“详情—收藏/个人中心—我的收藏”。
- **输入→输出**：收藏/取消、招募 ID → 唯一收藏关系及列表。
- **前端**：已结束仍保留在收藏中并显示状态；受限/删除目标只呈现安全占位（建议）。
- **后端**：认证、非封禁、重复操作幂等；收藏不赋予额外内容权限。
- **验收/边界**：重复点击无重复记录；结束不自动删收藏；取消后消失；下架不泄露原内容。
- **依赖/依据**：F-04、F-17；DEC-042、055。

### 3.5 M5 申请与审核

#### F-19 提交与重新申请（P0）

- **故事/入口**：作为认证学生，我希望申请具体岗位；入口“详情—岗位申请”。
- **输入→输出**：岗位 ID、选填留言 → 新 pending 申请或拒绝原因。
- **前端**：同招募不同岗位可分别申请；无留言可提交；曾拒绝/自行撤回可再次申请。
- **后端**：检查账号、招募开放且未截止、岗位有名额、黑名单；同用户同岗最多一条待审；保留每次申请历史，不覆盖旧结果。
- **验收/边界**：同岗并发重复申请仅一条待审；满员/结束/下架/封禁暂停拒绝；已在同招募占名额不能再占第二个；具体再次申请入口见 TD-11。
- **依赖/依据**：F-04、F-11、F-32、F-34～35；DEC-005～008；本次留言补充。

#### F-20 我的申请与我的队伍（P0）

- **故事/入口**：作为申请者，我希望跟踪自己的结果；入口“个人中心—我的申请/我的队伍”。
- **输入→输出**：当前用户 → 本人申请状态、原因、时间、关联招募岗位及通过历史。
- **前端**：展示待审/通过/未通过/撤回/过期，明确队伍是历史记录；公开投影按 F-07。
- **后端**：按本人过滤申请；保留重申请和自动变更历史；不返回其他录取者的成员清单。
- **验收/边界**：拒绝与撤销录取同为未通过，但原因可区分；正常结束后历史可回看；独立下架详情仍受限制。
- **依赖/依据**：F-07、F-19～26；DEC-013、017、034～036、038。

#### F-21 发布者申请审查（P0）

- **故事/入口**：作为发布者，我希望判断申请是否合适；入口“我的发布—申请管理”。
- **输入→输出**：本人招募/岗位、状态过滤 → 申请列表、选填留言、允许公开资料。
- **前端**：逐岗呈现、区分历史与待审；链接可访问的个人主页；不可用操作说明当前限制。
- **后端**：核验所有权；隐私开关不取消双方查看必要申请信息的权限；不得暴露申请者不必要的私密数据。
- **验收/边界**：其他用户无权读取列表；下架期间不能审核；业务必要访问不能变成浏览所有个人历史。
- **依赖/依据**：F-06～07、F-19、F-34；DEC-023、034、051。

#### F-22 通过申请与联动（P0）

- **故事/入口**：作为发布者，我希望录取申请者；入口“申请管理—通过”。
- **输入→输出**：pending 申请 → accepted、占位、自动撤回同人同招募其他待审、满员处理及通知事件。
- **前端**：只展示可处理申请；处理后刷新全部关联岗位和状态。
- **后端**：同事务校验资格和容量，禁止同人在同招募占第二岗位；该岗满员后拒绝剩余待审；全岗满员则立即 ended/filled。
- **验收/边界**：并发录取不得超额；自动撤回、满员拒绝、结束不得留下中间状态；最后名额导致正式结束后不能再撤销。
- **依赖/依据**：F-11、F-14、F-26、F-30；DEC-006、047～049。

#### F-23 拒绝申请（P0）

- **故事/入口**：作为发布者，我希望拒绝待审申请；入口“申请管理—拒绝”。
- **输入→输出**：pending 申请 → not_passed，原因 rejected，操作历史及结果通知。
- **前端**：将拒绝与撤销录取区别说明，统一显示未通过。
- **后端**：所有权、当前待审、允许审核校验；不占名额；失败不能重复发通知。原因编码为建议，不能遗漏原因类别。
- **验收/边界**：被拒绝者可再次申请有效岗位；结束或下架时禁止审核；重复拒绝不产生第二次业务变更。
- **依赖/依据**：F-21、F-30；DEC-007、017、051。

#### F-24 自行撤回与录取后放弃（P0）

- **故事/入口**：作为申请者，我希望撤回待审或在结束前放弃录取；入口“我的申请”。
- **输入→输出**：本人 pending/accepted 申请 → withdrawn，区分主动撤回/主动放弃原因；放弃释放名额并通知发布者。
- **前端**：两种动作使用不同说明；结束后禁用；撤回后可重新申请。
- **后端**：本人权限、时间与结果锁定校验；不把主动放弃写成发布者拒绝；暂停期间边界见 TD-07。
- **验收/边界**：结束前放弃释放准确一个名额；结束后不能改；重复撤回无重复影响。withdrawn 作为放弃终态是统一实现建议。
- **依赖/依据**：F-14、F-19、F-30；DEC-007、043。

#### F-25 发布者撤销录取（P0）

- **故事/入口**：作为发布者，我希望在结束前调整录取；入口“申请管理—撤销录取”。
- **输入→输出**：accepted 申请 → not_passed，原因 offer_revoked，释放名额、历史与通知。
- **前端**：提示正式结束后锁定，区分普通拒绝；不称为长期队伍成员移除。
- **后端**：所有权、未正式结束、未截止及允许交互校验；保存撤销录取与原通过历史。
- **验收/边界**：尚有空岗时可撤销；全岗满员结束后即不能撤销；不会自动恢复此前因满员未通过的申请。
- **依赖/依据**：F-14、F-22、F-30；DEC-012～014、017、048。

#### F-26 自动申请终态与容量（P0）

- **故事/入口**：作为参与者，我希望状态准确；后台自动处理，并在申请记录中展示。
- **输入→输出**：通过、满员、到期、拉黑事件 → 对应申请状态、原因及历史。
- **前端**：展示自动撤回、名额已满、截止过期、拉黑拒绝等业务结果，不泄露举报者。
- **后端**：同人其他岗待审 withdrawn；该岗其他待审 not_passed/capacity_full；到期待审 expired；拉黑相关待审 not_passed/blocked。没有候补，解黑不恢复旧申请。
- **验收/边界**：因释放名额而重新可申请只适用于尚未结束的招募；不自动重开旧申请或已结束招募；优先级按 03 第 4 节。
- **依赖/依据**：F-22、F-32、F-14；DEC-006、009、016、047～049。

### 3.6 M6 统一消息中心

#### F-27 自由文字私信（P0）

- **故事/入口**：作为认证学生，我希望与另一认证学生直接沟通；入口“主页—私信/消息中心”。
- **输入→输出**：接收人、文字 → 会话消息或拒绝原因。
- **前端**：一对一文字会话，可自愿发送联系方式和招募链接；告知管理员可查看全部会话及访问留痕机制。
- **后端**：发送双方认证、发送方非封禁、黑名单方向与互动资格校验；不要求先有申请关系；不提供正式邀请/自动加入。
- **验收/边界**：无招募关系可发送；被拉黑者不能发给拉黑者；不向发送者返回接收者已读标志；接收方封禁/注销的发送边界见 TD-07/05。
- **依赖/依据**：F-03、F-32、F-35、F-37；DEC-001、011、021、024、056、061。

#### F-28 消息列表与全站未读（P0）

- **故事/入口**：作为用户，我希望在任何页面知道新消息；入口“导航—消息中心”。
- **输入→输出**：本人身份、会话/通知读操作 → 会话列表、系统通知、全站未读数。
- **前端**：私信与简单系统通知在同一消息中心；导航持续显示未读；本人查看时更新自身读取状态。
- **后端**：只返回本人消息及通知；内部读取状态用于未读统计，不向发送者提供回执；私信与通知合计规则待 TD-09。
- **验收/边界**：其他页面仍更新未读；不能查看他人的未读/通知；自身读操作不会删除对方记录。封禁时阅读未读标记的内部写入例外需 TD-07 设计。
- **依赖/依据**：F-27、F-29～30；DEC-001、060～061。

#### F-29 HTTP 定时轮询（P0）

- **故事/入口**：作为用户，我希望定期获得消息更新；入口全站会话期间自动执行。
- **输入→输出**：会话、游标/时间范围（建议） → 新私信、通知、未读变化。
- **前端**：约 10 秒可配置轮询、失败提示和合理重试；页面关闭或退出后停止轮询。
- **后端**：认证访问、增量/分页、防重复；不采用 WebSocket。实际间隔、后台页面策略、游标待 TD-09。
- **验收/边界**：两客户端轮询可收消息；失败后恢复不丢失或重复展示；不承诺即时送达，也不通过长连接替代确认方案。
- **依赖/依据**：F-02、F-28；DEC-059～060。

#### F-30 简单系统通知（P0）

- **故事/入口**：作为参与者，我希望知道申请与治理结果；入口“消息中心—系统通知”。
- **输入→输出**：业务提交事件 → 指定接收者的站内通知、安全链接及未读变化。
- **前端**：展示结果摘要，链接访问时重新检查资源权限；不建立复杂通知平台。
- **后端**：按 [通知事件表](03-business-rules.md#8-通知事件表) 投递，业务成功后才发，建议幂等重试；下架/恢复通知全部历史申请者，去重。
- **验收/边界**：失败事务不发成功通知；处罚消息不泄露举报者身份；下架申请者通知不含具体原因；过期申请者得到通知。未定事件不宣称已确认。
- **依赖/依据**：M3/M5/M7；DEC-001、016、043、052～053、058、060。

#### F-31 私信个人侧删除与会话隐藏（P0）

- **故事/入口**：作为用户，我希望整理自己的消息列表；入口“会话—删除消息/隐藏会话”。
- **输入→输出**：本人可见消息/会话 ID → 个人可见性变化。
- **前端**：说明仅对自己生效，不作为双方撤回；隐藏后新消息再显示策略待 TD-09。
- **后端**：用户侧删除标记、会话隐藏标记；不销毁对方副本及必要服务器记录，管理员证据访问不受个人隐藏替代。
- **验收/边界**：A 删除后 B 仍能看到；A 隐藏不改变 B 列表；不能伪造或修改消息；封禁用户不得执行此业务写入。
- **依赖/依据**：F-27～28、F-37；DEC-055、064。

### 3.7 M7 治理与管理后台

#### F-32 用户级黑名单（P0）

- **故事/入口**：作为用户，我希望阻止特定人继续联系和申请；入口“主页/会话—拉黑、个人中心—黑名单”。
- **输入→输出**：目标用户、拉黑/解黑 → 有向黑名单及相关待审处理。
- **前端**：说明影响对方对自己的全部招募与私信；不宣称双方全面不可见。
- **后端**：拉黑事务拒绝目标对本人全部招募的 pending 申请，保留历史；阻止该方向新申请/私信；解黑不恢复旧申请。
- **验收/边界**：跨多条招募全部待审处理；既有 accepted 不因拉黑自动撤销；不触发长期团队移除；反向联系是否额外限制不擅自扩大。
- **依赖/依据**：M5、F-27、F-30；DEC-008～010、013。

#### F-33 举报提交（P0）

- **故事/入口**：作为认证用户，我希望报告违规；入口“招募详情/用户主页/具体私信—举报”。
- **输入→输出**：目标类型与 ID、理由 → 举报记录及提交结果。
- **前端**：三种举报入口，私信指向具体消息；不许填写举报即自动封禁的提示。
- **后端**：校验目标及提交者权限，保存人工处理记录；不自动下架/封禁；证据快照与重复举报规则待 TD-10。
- **验收/边界**：他人私信不可通过猜 ID 举报读取；提交后业务对象不自动处罚；不能向被举报者暴露身份。
- **依赖/依据**：F-04、F-17、F-27、F-39；DEC-025～026、058。

#### F-34 招募管理：下架与恢复（P0）

- **故事/入口**：作为管理员，我希望独立处置招募内容；入口“后台—招募管理”。
- **输入→输出**：未结束、未到期招募与处置原因 → 独立下架/恢复状态、记录及通知。
- **前端**：区分正式结束、独立下架、封禁暂停；恢复时展示是否仍受封禁影响。
- **后端**：独立管理标记，不改变截止；下架期间暂停申请/审核、保留待审；到期仍结束且待审过期；恢复不得重开结束招募或绕过封禁。
- **验收/边界**：通知发布者及全部曾申请者；申请者看不到下架具体原因；截至恢复时已到期不能恢复；多原因暂停仅清除相应原因。
- **依赖/依据**：M3/M5、F-30、F-35；DEC-003、049～053。

#### F-35 用户管理：封禁与解封（P0）

- **故事/入口**：作为管理员，我希望按核实结果暂停账号；入口“后台—用户管理”。
- **输入→输出**：用户、手动封禁/解封、封禁必填原因 → 账号状态、招募联动及审计。
- **前端**：显示原因和操作历史，不设自动解封期限；封禁用户端呈只读。
- **后端**：隐藏所有尚未结束的本人招募、暂停交互；解封只自动恢复仅因封禁隐藏且未截止未结束者；独立下架标记保留。
- **验收/边界**：空原因不能封禁；封禁可登录但不能发布/申请/审核/发消息或其他业务写入；解封不恢复违规下架或已结束招募；不擅自删除存量申请。
- **依赖/依据**：F-04、F-14、F-34、F-30；DEC-027～028、054～055。

#### F-36 分类与标签管理（P0）

- **故事/入口**：作为管理员，我希望维护分类和标签；入口“后台—分类标签”。
- **输入→输出**：分类/招募标签/技能兴趣标签、维护或合并操作 → 更新字典及引用。
- **前端**：一级分类仅从预设选项选择，普通用户不能创建分类；标签允许学生新增。
- **后端**：维护不合适标签、合并重复标签；引用中的分类/标签变更不得产生孤立记录。具体停用/删除策略待 TD-10。
- **验收/边界**：合并后个人搜索和招募检索引用一致；不能因删标签误删招募/申请；初始分类名称非硬编码决策。
- **依赖/依据**：F-05、F-10、F-15；DEC-029、063、066。

#### F-37 私信管理与访问审计（P0）

- **故事/入口**：作为管理员，我希望核查任意会话且留下责任记录；入口“后台—私信管理”。
- **输入→输出**：目标会话、必填访问原因 → 该会话全部消息及不可随意修改删除的访问审计。
- **前端**：原因填写在内容访问之前；明确不限举报上下文；不提供改写、伪造消息或审计删除按钮。
- **后端**：每次敏感访问校验授权与有效访问范围；记录管理员身份、会话、时间、原因；审计成功前不能返回正文。分页/重新进入是否复用同次原因见 TD-08。
- **验收/边界**：空原因/审计失败不能读正文；个人侧隐藏/删除不使必要管理记录消失；直接管理接口同样受控；普通后台无法修改删除访问日志。
- **依赖/依据**：F-04、F-27、F-31；DEC-056 最终修订版、057、064、066。

#### F-38 自主注销（P0）

- **故事/入口**：作为用户，我希望退出平台并清理资料；入口“账号设置—注销”。
- **输入→输出**：身份验证、二次确认 → 注销结果及按设计完成的数据删除/匿名化。
- **前端**：确认前清楚列出实际清理和保留规则，不宣称所有业务数据立即删除。
- **后端**：身份核验、注销账号与会话失效；清理不再必要个人信息，妥善处理关联历史；活动招募/申请/消息/审计策略见 TD-05，须先完成设计再实现。
- **验收/边界**：缺验证/确认不得注销；完成后原账号不能继续登录或业务写入；历史关联不能损坏；封禁者注销入口及原邮箱再注册待设计。
- **依赖/依据**：M1～M7；DEC-065。此功能必须交付，数据策略待定不意味着将整个注销移至 P1。

#### F-39 举报人工处置与管理历史（P0）

- **故事/入口**：作为管理员，我希望核实并闭环举报；入口“后台—举报管理”。
- **输入→输出**：举报、核实结果、处置结论/理由 → 驳回或处置完成、必要下架/封禁操作、通知和审计。
- **前端**：查看举报对象及必要证据，选择处置；不另设审核员角色、统计看板。
- **后端**：人工结论与处罚动作分别记录，调用 F-34/35；若看会话须经过 F-37；处置通知举报者，处罚则也通知受处罚者。
- **验收/边界**：举报者身份及可能识别其身份的证据不进入受罚通知；重复处理不重复处罚；失败不能伪称已处罚；管理操作可追溯且不伪造旧记录。
- **依赖/依据**：F-33～35、F-37、F-30；DEC-025～026、054、057～058、066。
