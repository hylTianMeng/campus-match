# 业务规则、状态与权限

核对日期为 2026 年 11 月 16 日。

## 身份与资源权限

| 操作 | 当前检查 |
| --- | --- |
| 注册与找回 | 校园注册域名校验、邮箱唯一、密码和验证码规则 |
| 发布、保存、申请、审核、收藏修改、私信 | `student` 检查已认证且未封禁，具体操作再检查资源关系 |
| 本人申请、消息和通知查询 | 当前登录用户，查询限制到本人业务范围 |
| 发布者查看申请 | 当前登录用户且拥有该招募 |
| 完整同学主页与搜索 | 当前登录且已认证，目标按可见性条件筛选 |
| 用户管理 | 管理员且未封禁，封禁禁止处理本人及其他管理员 |
| 注销 | 当前登录、密码验证，前端进行二次确认，封禁用户也可执行 |

注销后账号匿名化，原邮箱释放，会话删除。与活动招募、申请、消息和审计的数据关联策略仍需补齐。验证码发送、已读写入等少数操作采用 `current_user`，封禁状态下的完整业务边界需要统一验证。

## 招募生命周期与编辑

| 状态或动作 | 当前行为 |
| --- | --- |
| 草稿 | 私有，允许缺项，前端自动保存及手动保存 |
| `open` | 允许有效角色申请，受认证、容量和账号限制 |
| `ended / filled` | 所有岗位满员后立即结束，锁定录取结果 |
| `ended / expired` | 截止到期，待审申请过期，通过结果保留 |
| `ended / manual` | 发布者提前结束，当前要求没有待审核申请 |
| 进行中编辑 | 可调整分类、岗位、安排、名额，截止时间仅可延长 |
| 已结束编辑 | 可修正说明、联系方式和补充资料，标题、标签、地点、岗位与时间锁定 |
| 岗位删除 | 有任意申请历史即拒绝，发布者可停止接收新申请 |
| 招募删除 | 有任意申请历史即拒绝，历史撤回或拒绝也计入 |
| 复制 | 生成独立草稿并复制相关附件，原记录保留 |

岗位容量不得低于已录取数。编辑缩减容量达到满员时处理剩余待审并检查整条招募结束。岗位变化通知该岗曾申请者，时间、地点或截止变化通知待审及通过者。

## 申请状态与容量

| 动作 | 状态转换及联动 |
| --- | --- |
| 提交 | 新建 `pending`，写申请事件并通知发布者 |
| 通过 | `pending → accepted`，同用户其他岗待审转 `withdrawn` |
| 满岗 | 该岗剩余待审转 `rejected`，原因记录名额已满 |
| 拒绝 | `pending → rejected`，保存拒绝原因和通知 |
| 撤销录取 | `accepted → rejected`，保存撤销原因并释放名额 |
| 撤回 | `pending → withdrawn`，通知本人及发布者 |
| 放弃录取 | `accepted → withdrawn`，释放名额并通知 |
| 到期 | 待审转 `expired`，写历史和通知 |

一人可申请同一招募多个岗位，但同岗最多一个待审，同一招募最多一个通过。数据库部分唯一索引和事务共同保护名额。正式结束后状态调整被拒绝。

当前允许已拒绝或撤回等非占位状态重新申请，撤销、放弃后的资格需与最终产品口径统一。手动结束时待审结果尚未另行定义，继续使用先处理完待审的限制。

## 公开范围与已知差异

- 申请留言、经历、简历或作品链接只在本人申请和发布者申请管理返回。
- 游客可见发布者昵称与头像，完整资料依赖认证身份。
- 搜索开关控制用户搜索，组队历史公开只返回招募和本人岗位。
- 当前 `public_posts` 还影响大厅列表和普通用户的直接详情访问，本人和管理员在详情拥有例外。代码对此标注待组长确认，旧方案曾仅影响主页栏目，后续需统一取舍。
- 发布者封禁时，公开招募列表及详情会隐藏其内容，详情限制还覆盖其已结束招募。本人收藏、主页历史和附件等入口的可见性处理尚未统一。
- 注销后关闭公开开关，部分查询仍缺少明确的注销条件。头像和会话已有注销检查，关联招募、申请和消息需继续核对。

## 消息与通知

认证且未封禁的用户可向另一名认证且未封禁用户发文字私信，无需先申请招募。读取接口限定当前用户参与的会话。正文最长 4,000 字符，返回数据包含时间与发送接收人，内部已读标记用于未读统计。

私信每批最多 200 条，客户端按 `after` 游标连续读取，约 10 秒轮询。会话按最后消息时间排序。系统通知读取最近 200 条，提供全部标为已读。导航显示私信加系统通知的未读总数。

业务成功时在同一数据库事务写通知。当前通知保存正文、用户、招募引用和时间，缺少事件类型、去重键及通用重试设施。消息发送超时后的重试也缺少请求幂等键。

私信粘贴的招募链接当前按纯文本展示，自动生成可点击链接和结构化招募分享卡片待开发。

## 治理目标与实现缺口

| 目标规则 | 实现情况 |
| --- | --- |
| A 拉黑 B 后，阻止 B 向 A 私信及申请 A 的全部招募 | 关系、入口和校验待开发 |
| 拉黑时拒绝相关待审，既有录取保留，解黑不恢复旧申请 | 跨 B/D 事务联动待开发 |
| 仅对自己删除消息或隐藏会话，对方仍能查看 | 个人可见性标记与接口待开发 |
| 招募、用户、具体消息可举报，提交后交管理员人工处理 | 举报链路待开发 |
| 独立下架与账号封禁可同时存在，恢复仅清除对应限制 | 独立下架及恢复待开发，当前已有账号封禁 |
| 下架不延长截止，下架期间到期仍结束 | 治理和生命周期整合待开发 |
| 管理员访问任意会话先填原因并成功记审计 | 敏感访问后台与审计待开发 |
| 举报处理与处罚结果通知双方，受罚者看不到举报者资料 | 举报通知待开发，现有封禁通知只有简短状态 |
