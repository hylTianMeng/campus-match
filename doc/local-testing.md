# 本地运行与测试指南

本机已配置 Node.js 22.22.0、Python 3.12 虚拟环境、前后端依赖、Chrome 浏览器测试、开发配置与演示数据。当前使用 SQLite，数据保存于 `backend/data/campuscrew.sqlite3`。

## 访问页面

- 网站地址为 <http://127.0.0.1:5173/>。
- API 文档地址为 <http://127.0.0.1:8000/docs>。
- 健康检查地址为 <http://127.0.0.1:8000/api/health>。

页面通过 Vite preview 提供生产构建，API 代理到 FastAPI。服务绑定本机 `127.0.0.1`。服务启动后可关闭启动它的终端，重启电脑后需要重新启动服务。

## 启动、查看和停止

从项目根目录执行。

```bash
cd /Users/Admin/campus-match

# 启动，自动构建前端并等待前后端健康检查
python3 scripts/local.py start

# 查看服务 PID 和健康状态
python3 scripts/local.py status

# 停止这套脚本启动的服务
python3 scripts/local.py stop
```

修改代码后，先执行 `stop` 再执行 `start`，页面会使用重新构建的版本。刷新浏览器即可检查。

本机 Node.js 位于 `.run/node-v22.22.0-darwin-arm64/`，快捷命令位于 `.run/bin/`。后端虚拟环境位于 `backend/.venv/`。管理脚本自动使用这些路径。

## 手工测试步骤

### 1. 公开浏览

打开首页，搜索“碳足迹”，切换分类和排序，进入详情查看说明、岗位及补充信息。访问完整功能示例，检查附件下载是否正常。

### 2. 发布与草稿

使用陈书宁登录，新建一条“测试乐队招募”或“测试志愿者招募”。先只填写标题并手动保存草稿，再从草稿箱恢复。补齐分类、说明、未来的截止时间和至少一个岗位，正式发布。

在补充信息区点击“添加自定义信息”，设置标题和属性，可添加文字、网址或附件。附件支持 PDF、DOCX、PNG、JPG 和 TXT，每个最大 5 MB。发布后进入详情确认内容与下载链接。

### 3. 跨账号申请与审核

1. 保持陈书宁的窗口打开，复制新招募详情地址。
2. 用浏览器无痕窗口或另一款浏览器登录林知夏，打开详情地址。
3. 点击“一键参与”，选择岗位，填写留言或作品链接并提交。
4. 回到陈书宁窗口，从“管理发布”进入对应的申请管理，查看资料并通过或拒绝。
5. 回到林知夏窗口，在“当前申请”和消息中心查看结果。

建议创建两个岗位，每岗一人，测试同一人申请两岗后只被录取一岗。若希望测试“录取后放弃”或“撤销录取”，需让整条招募仍有空余岗位。所有岗位满员后会结束并锁定结果。

### 4. 资料、隐私、收藏和私信

编辑昵称与简介并保存，检查公开主页。关闭搜索可见性后，用另一账号搜索该昵称。收藏招募后进入“我的收藏”确认记录。打开同学主页发起私信，在另一个窗口检查消息。消息与未读数量约每 10 秒刷新。

### 5. 注册、认证与密码找回

当前配置为 `SMTP_ENABLED=0`，使用开发验证码。注册一个新的 `@mails.tsinghua.edu.cn` 或 `@tsinghua.edu.cn` 地址，点击发送验证码，页面会显示“开发态验证码”，后端日志也会记录。填写验证码完成认证。

密码找回同样使用页面显示的开发重置码。新测试账号可用于头像上传及注销测试。开启真实邮件需要在 `backend/.env` 配置 SMTP 账号和授权码并设置 `SMTP_ENABLED=1`，然后重启后端。

### 6. 用户管理

使用林知夏登录，访问 <http://127.0.0.1:5173/#/admin>。选择新建的测试账号，填写原因后封禁，再使用该账号检查操作限制，最后解封。避免修改仍在演示中的主测试账号，以便继续其他测试。

## 自动化测试

在项目根目录执行全套检查。

```bash
cd /Users/Admin/campus-match
python3 scripts/local.py test
```

命令依次执行 31 项后端测试、TypeScript 检查及生产构建、7 项 Playwright 浏览器测试。浏览器测试使用 Chrome，自动启动临时后端与前端，端口分别为 8001 和 5174。后端及浏览器测试使用临时数据库，可在本地部署运行期间执行。

如需单独检查，可执行以下命令。

```bash
cd /Users/Admin/campus-match

# 后端测试
(cd backend && .venv/bin/python -m pytest -q)

# 当前终端使用本项目的 Node.js 和 npm
export PATH="$PWD/.run/bin:$PATH"

# 类型检查和生产构建
npm --prefix frontend run build

# 浏览器测试
npm --prefix frontend run test:e2e
```

测试覆盖公开浏览与手机布局、草稿和附件保存、发布、跨账号申请审核、通知、隐私与私信，以及后端权限和并发名额。配置完成时另在临时数据库验证了注册、开发验证码、密码重置、注销和管理员访问。

## 消息与治理测试入口

- 个人中心的黑名单和我的举报可查看自己的关系与处理进度。
- 会话支持可点击招募链接、选择本人招募分享、仅本人删除、隐藏和拉黑。新消息会重新显示隐藏会话。
- 用户主页、招募详情和具体接收消息均可举报。
- 管理员在 `/admin/reports` 核实举报，在 `/admin/posts` 下架或恢复招募，在 `/admin/messages` 填原因查看会话。
- `/admin/audits` 展示只读访问审计，`/admin/history` 展示账号和招募处罚历史。
- 封禁和独立下架分别生效，解封不会清除下架，恢复不会解除封禁。到期后不能恢复。
- 私信举报说明和原始会话只在成功记录审计后展示，单次授权 15 分钟，过期重新填写原因。

本地测试版的消息、举报与审计数据持续保存在数据库，当前没有自动清理任务。个人删除和隐藏仅更改本人视图，账号注销保留相关历史。数据库触发器禁止普通应用连接改删访问审计，拥有数据库文件管理权限的维护者仍可进行离线维护，应先备份并明确清理范围。
