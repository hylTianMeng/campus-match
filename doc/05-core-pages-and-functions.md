# CampusCrew 核心界面页面与功能对应说明

日期：2026-10-29　适用：第一轮静态网站原型制作

本轮以电脑浏览器网站为主，兼容手机浏览器。制作范围收敛为 8 个核心页面，展示“发布招募 → 查找招募 → 申请岗位 → 发布者审核 → 查看结果”的完整流程。收藏、草稿、个人资料与组队历史通过现有页面的标签页承载，不增加独立页面。

本文是第一轮制作清单；[完整页面设计](04-pages-and-functions.md)作为后续功能储备保留。本轮暂缓的功能不表示已从最终产品需求中删除。页面布局、合并方式及路径为原型设计建议。

## 1 网站整体结构

学生端统一使用顶部导航：**发现组队、发布招募、我的招募、我的申请、个人中心**。右侧放简单通知入口及账号菜单。申请管理从“我的招募”的具体招募进入，不占一级导航。

登录前可浏览招募广场和公开详情；点击申请、发布、收藏等操作时引导登录及校园认证。登录后同一账号既可发布也可申请，不拆分“队长账号”和“队员账号”。

```text
登录与注册
    ↓ 返回原入口
招募广场 → 招募详情 → 提交岗位申请 → 我的申请
               ↑                         ↑
发布与编辑 → 我的招募 → 申请管理 → 审核结果
    ↑           │
    └── 草稿 ───┘

个人中心：基本资料 / 我的收藏 / 组队历史
顶部通知面板：查看申请结果 → 跳转对应记录
```

## 3 逐页布局与操作说明

### P01 登录与注册

**目的**：建立校园身份，让用户回到原来的发布或申请任务。

**布局**：居中账号表单，顶部显示品牌及校园组队说明，下方切换登录/注册；注册后进入邮箱验证码步骤。

- 登录字段：校园邮箱、密码。
- 注册字段：昵称、校园邮箱、密码；认证步骤输入邮件验证码。
- 操作：登录、注册、发送/重新发送验证码、验证、返回浏览。
- 登录或认证成功后返回原页面，不自动提交申请或发布招募；账号菜单支持退出登录。

**必要状态**：字段缺失、邮箱已注册、登录失败、验证码错误或过期、发送失败、认证成功。邮箱域名和验证码时效使用可配置占位，不在静态方案里锁定。

### P02 招募广场

**目的**：作为网站首页，让用户快速找到可以参与的招募。

**布局**：顶部搜索框 → 分类与筛选区 → 已选条件和排序 → 招募卡片列表 → 分页。不另做宣传首页。

- 搜索：标题、描述、标签关键词。
- 筛选：一级分类、标签、是否仍可申请、截止时间范围、活动地点；高级条件可折叠，支持组合及清空。
- 排序：默认最新发布，可切换即将截止。
- 卡片：标题、分类、简介、标签、岗位摘要、录取人数/总名额、截止时间、可选活动地点及发布者昵称头像。
- 点击卡片进入 P03；顶部发布入口进入 P04。

**必要状态**：正常列表、加载、无招募、无匹配结果、加载失败。默认不展示已结束招募，历史从本人记录或收藏回看。

### P03 招募详情

**目的**：帮助用户判断是否适合，并针对具体岗位申请。

**布局**：左侧为标题、分类标签、招募说明、活动安排和岗位卡；右侧为发布者昵称头像、截止时间、收藏及操作提示。手机上改为单栏。

- 每个岗位显示名称、描述、技能要求、已录取/总名额、剩余名额。
- “申请此岗位”打开弹窗，确认岗位并填写选填留言，提交后显示待审核；不同岗位分别申请。
- 支持收藏/取消收藏，收藏可在 P08 找回。
- 发布者查看自己的招募时显示“编辑招募”“管理申请”，分别进入 P04、P06。
- 已提交申请的用户可进入 P07 查看记录。

**必要状态**：可申请、该岗待审核、岗位已满、已在本招募通过、已结束、内容不可用。正常结束的详情保留正文和结束原因，申请关闭。

本轮不放私信、举报、完整同学主页或其他录取成员名单入口。

### P04 发布与编辑

**目的**：用同一套表单完成新建、草稿继续填写与已发布内容修改。

**布局**：基本信息 → 岗位列表 → 时间地点与标签 → 底部操作栏。

| 区块 | 字段 | 规则 |
| --- | --- | --- |
| 基本信息 | 标题、一级分类、描述 | 正式发布必填 |
| 岗位列表 | 岗位名称、人数、岗位描述、技能标签 | 至少一岗；名称人数必填，人数为正整数；发布前可增删 |
| 时间安排 | 招募截止时间、活动时间 | 截止必填，活动时间选填 |
| 地点和标签 | 活动地点、招募标签 | 选填；可选已有标签或新建标签 |

三种模式的操作区别：

- **新建**：保存草稿、发布。保存草稿允许缺字段，发布执行完整校验，成功后立即公开并进入 P03。
- **草稿编辑**：保存草稿、正式发布，进入时恢复已有内容。
- **已发布编辑**：修改标题、描述、地点、招募标签等已确认一般字段；岗位增删、名额和截止时间锁定。岗位一般字段及活动时间能否修改尚待细化，先只读。

**必要状态**：字段错误、保存中、保存成功、失败保留内容、冻结字段说明。没有自动保存、图片或附件上传；已结束及管理暂停时的编辑边界未定，先用只读示例。

### P05 我的招募

**目的**：集中管理自己的招募和草稿。

**布局**：顶部新建按钮 → “已发布/草稿”标签 → 状态筛选 → 列表。

| 标签页 | 展示内容 | 操作 |
| --- | --- | --- |
| 已发布 | 标题、逐岗录取进度、待审核数、截止、当前状态 | 详情、编辑、管理申请、提前结束、符合条件时删除 |
| 草稿 | 标题或未命名招募、最近手动保存时间、岗位摘要 | 继续编辑、删除 |

编辑或继续草稿进入 P04，管理申请进入 P06。提前结束必须确认“结束后结果锁定，不能重新开放”。已发布招募有任何申请历史便不能删除，即使申请后来全部撤回或未通过；此时只在尚未结束时提供提前结束。

**必要状态**：无发布、无草稿、招募中、已招满、已截止、提前结束、删除受限、操作失败。已结束记录保留，不能通过修改或补招按钮重新开放。

### P06 申请管理

**目的**：让发布者针对一条招募逐岗审核。

**布局**：招募摘要 → 岗位切换与名额 → 申请状态筛选 → 申请列表 → 详情抽屉。

- 申请信息：昵称头像、必要资料摘要、岗位、提交时间、留言、状态和操作历史。
- 待审核：通过、拒绝；拒绝记录原因，可用输入框呈现。
- 已通过：招募尚未结束时可撤销录取，并保留原因和历史。
- 通过确认：提示会自动撤回同一人在本招募其他岗位的待审；如果该岗将满，提示其他待审将因满员未通过；如果全部岗位将满，提示立即结束且结果锁定。
- 审核成功后，岗位人数、申请列表、P05 状态及结果通知使用一致的样例状态。

**必要状态**：无申请、待审核、已通过、未通过、全岗满员立即结束、结果已锁定、申请已处理或名额变化冲突。非发布者不能查看此页；不提供批量自动录取。

### P07 我的申请

**目的**：跟踪本人申请结果，保留历次提交记录。

**布局**：全部/待审核/已通过/未通过/已撤回/已过期筛选 → 申请记录列表 → 展开历史。

- 记录展示招募、岗位、提交时间、本人留言、状态、原因及相关时间。
- 待审核可撤回；被拒绝或本人主动撤回后，岗位仍开放且资格满足时可重新申请。
- 已通过且招募尚未结束时可放弃录取；结束后结果锁定，不能放弃。
- 重新申请新增记录，旧申请仍可回看；同一招募不同岗位分别展示。
- 点击招募进入 P03；自动撤回、普通拒绝、满员未通过、撤销录取及截止过期使用不同原因说明。

**必要状态**：无申请、两岗同时待审、一岗通过另一岗自动撤回、满员未通过、到期过期、结束锁定、撤回/放弃确认、重复提交冲突。

提前结束时待审申请的终态未确定，原型显示招募已结束及待定说明，不擅自写成截止过期。撤销录取、自动撤回、放弃等场景的再次申请资格也不扩大解释。

### P08 个人中心

**目的**：用一个页面承载基础资料及两个辅助历史视图。

**布局**：个人资料摘要 → “基本资料/我的收藏/组队历史”三个标签页。

| 标签页 | 内容与操作 | 展示边界 |
| --- | --- | --- |
| 基本资料 | 编辑昵称、头像、院系、年级、简介、技能兴趣标签；选择或创建标签，保存 | 昵称必填，其余选填；校园邮箱只在本人账号信息中展示 |
| 我的收藏 | 收藏卡片、取消收藏、进入 P03 | 已结束招募仍保留；不可用内容安全占位，不泄露隐藏正文 |
| 组队历史 | 通过的招募、本人岗位、通过时间、招募状态、详情入口 | 不是团队管理，无成员列表、聊天室、任务或踢人操作 |

**必要状态**：空资料选填项、昵称错误、保存成功/失败、无收藏、结束收藏、无组队历史。先展示仍保持通过结果的组队记录，曾通过后撤销或放弃是否收录待后续确认。

## 4 页面之间的交互对应

| 用户操作 | 起点 | 终点或反馈 |
| --- | --- | --- |
| 未登录点击发布、申请、收藏 | P02/P03 或导航 | P01，成功后回原页面继续操作 |
| 查看招募 | P02/P05/P07/P08 | P03 |
| 发布新招募 | 导航/P05 | P04 → P03，并出现在 P05 |
| 保存、继续或删除草稿 | P04/P05 | P05 草稿标签或 P04 草稿编辑 |
| 修改已发布招募 | P03/P05 | P04 已发布编辑模式 |
| 申请某岗位 | P03 | 申请弹窗 → 待审核提示 → P07 |
| 管理申请 | P03/P05 的本人招募 | P06 |
| 审核通过或拒绝 | P06 | 列表和名额更新；申请者 P07 与通知展示结果 |

## 5 本轮保留与暂缓范围

### 必须保留的业务约束

1. 多岗位独立名额，同人可申请不同岗，但同岗不能同时重复待审。
2. 一个招募最多录取同一人一次，一岗通过自动撤回其余岗位待审。
3. 岗位满员后停止申请并使该岗其他待审未通过；全岗满员立即结束，无七天确认期或候补。
4. 到期、招满、手动结束均不可重开；结束后不能调整录取结果。
5. 发布后不能增删岗位、修改名额或截止；任何申请历史都会阻止删除。
6. 草稿手动保存且私有；公开列表与本人申请资料有明确区别。

### 本轮暂缓的页面和能力

找同学与完整他人主页、完整私信中心、复杂系统通知、隐私设置、举报拉黑、注销流程、五类管理后台。基础展示仍需保留加载、失败、无权限、内容不可用等反馈，以便后续接入治理规则。

收敛页面不等于取消约束；但本轮不要求演示尚未制作的后台治理闭环或完整账号生命周期。若课程最终交付也需要删减这些功能，应另行同步原需求范围。

## 6 静态制作和验收清单

### 制作顺序

1. 顶部导航、统一卡片、表单、状态标签、确认弹窗及全局反馈。
2. P02 招募广场、P03 详情、P04 发布、P05 我的招募。
3. P06 申请管理、P07 我的申请、简单结果通知。
4. P01 账号认证、P08 个人中心，补齐身份和窄屏变体。

### 必须走通的演示

| 场景 | 操作链路 | 验收重点 |
| --- | --- | --- |
| 浏览并认证申请 | P02 → P03 → P01 → P03 → P07 | 认证前不提交，认证后回原任务 |
| 草稿到发布 | P04 保存缺项草稿 → P05 继续 → P04 发布 | 手动保存、完整校验、发布即公开 |
| 编辑与删除限制 | P05 → P04；有历史时尝试删除 | 冻结字段、有历史不能删除 |
| 多岗位申请审核 | P03 申请两岗 → P06 通过一岗 → P07 | 一人一名额、另一岗自动撤回 |
| 满员结束 | P06 录取最后名额 → P03/P05/P07 | 该岗其他待审未通过，全岗满员立即锁定 |
| 撤回与重新申请 | P07 撤回 → P03 重申 → P07 | 新旧记录均保留，无重复待审 |
| 放弃或撤销录取 | 未结束招募的 P07/P06 → 对比已结束记录 | 仅未结束时释放名额，结束后禁用 |
| 截止与手动结束 | 到期样例；P05 提前结束 | 三种结束原因区分，手动待审终态不擅定 |
| 收藏与组队历史 | P03 收藏 → P08；申请通过后查看组队历史 | 结束收藏留存、无长期队伍管理 |
| 异常反馈 | 表单缺项、搜索无结果、旧页面提交遇到名额变化 | 清楚提示并可重试或刷新，不显示虚假成功 |

每个页面至少有正常状态及适用的空、加载、失败状态；关键操作都有跳转、弹窗、反馈或附原因的禁用。桌面优先完成，手机窄屏保证导航、岗位申请、表单提交、审核及返回入口可用。

演示使用虚构数据及本地状态。真实认证、权限、持久化、并发名额、消息更新与审计留给后续系统实现，静态演示不作为这些能力的完成证明。
