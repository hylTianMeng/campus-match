# 校园组队与人员招募平台产品概述

更新日期为 2026 年 11 月 16 日。

## 背景与目标

校园中的组队需求覆盖课程作业、学科竞赛、科研合作、乐队组建、游戏搭子、问卷参与、志愿者招募和兴趣活动。群聊和熟人渠道中的信息容易沉底，参与条件、角色分工、剩余名额及申请结果难以持续跟踪。

平台定位为单校服务。发起者围绕具体活动发布招募，设置角色、条件、人数与时间，参与者通过搜索、申请和沟通找到适合自己的机会。平台记录招募与匹配结果，实际合作可在线下或其他工具中开展。

| 目标 | 产品能力 |
| --- | --- |
| 集中发现机会 | 分类、关键词、技能兴趣标签、排序与收藏 |
| 清楚表达参与需求 | 统一表单、多岗位、活动安排、自定义信息及附件 |
| 跟踪匹配结果 | 独立申请、审核、状态历史与系统通知 |
| 保持名额准确 | 同招募一人一名额、满岗处理、结束锁定 |
| 保护个人资料 | 私有申请资料、公开范围和会话访问控制 |
| 处理骚扰与违规 | 黑名单、举报、处罚及敏感访问审计，治理闭环继续开发 |

## 用户与身份

| 用户 | 场景与需求 |
| --- | --- |
| 招募发起者 | 为项目、活动或兴趣组队寻找合适的参与者，按角色管理名额 |
| 参与者 | 按技能、兴趣和安排选择机会，提交资料并查看结果 |
| 初次访问者 | 浏览公开招募，了解参与要求，交互时完成登录和校园认证 |
| 管理员 | 管理用户，后续核实举报、处理招募和审计敏感访问 |

一个普通用户可以同时发布和申请不同招募。发布者、申请者由资源关系决定。账号有认证、封禁及注销状态，管理资格由 `is_admin` 标记和服务端权限检查决定。

## 当前功能与后续范围

| 模块 | 当前进展 | 后续工作 |
| --- | --- | --- |
| 账号与用户 | 注册、登录、校园认证、找回密码、头像、资料、隐私、注销和用户管理已具备代码链路 | 真实 SMTP 环境验收、注销关联业务清理和封禁影响完善 |
| 招募与发现 | 自动及手动草稿、发布编辑、多岗位、多附件、复制招募、标签搜索、排序、收藏已实现 | 完整筛选分页界面、分类标签后台、独立下架恢复 |
| 申请与匹配 | 提交审核、撤回放弃、撤销、名额联动、到期及满员结束、历史已实现 | 申请筛选分页、手动结束待审策略及治理联动 |
| 消息与治理 | 基础私信、会话、通知、未读、轮询以及用户封禁已实现 | 个人消息删除隐藏、黑名单、举报、私信审计及治理结果通知 |

账号邮件接口支持开发验证码和 SMTP。当前本地部署采用开发验证码，真实邮件投递尚待配置和验证。

## 四人功能归属

| 协作组 | 负责人 | 主责 |
| --- | --- | --- |
| 用户与交流 | A | 账号、资料、用户发现、隐私、注销、后台用户管理 |
| 用户与交流 | B | 私信通知、黑名单、举报处理、后台私信与访问审计 |
| 招募与匹配 | C | 发布草稿、检索收藏、分类标签、后台招募管理 |
| 招募与匹配 | D | 申请审核、容量、生命周期、申请与组队历史 |

每个人负责本功能的页面、接口、数据和测试。A 提供身份资格，B 提供消息与治理关系，C 提供招募与管理限制，D 负责容量和状态联动。

## 设计边界

目前采用主动搜索和两种时间排序，沟通采用一对一文字私信及 HTTP 轮询。组队历史由申请结果形成，名额满员或正式结束后保留历史。跨校、支付、智能推荐、长期成员管理、群聊和音视频尚未纳入当前开发范围。

问卷调查场景支持招募参与者和提供问卷链接。乐队、游戏和志愿服务场景共用角色、名额与申请模型。
